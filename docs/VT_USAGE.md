# ish 설정 안내

현재 제품은 libghostty-vt + PTK 기반 **ish** 하나다. 설치된 `ish`, 소스의 `python -m ish`가 같은 경로이며 예전 stream 실행기와 `ish-vt` 별칭은 제공하지 않는다. 처음 실행하는 방법은 [README](../README.md), 지원 범위와 제약은 [기능 정책](VT_FEATURE_POLICY.md)과 [SIXEL 안내](VT_SIXEL.md), 구현 계약은 [AGENTS.md](../AGENTS.md)를 참고한다.

## TUI로 익히기

```sh
ish -h                       # 카테고리별 도움말
ish --help --lang ko
ish --help > ish-help.txt     # 같은 문서를 일반 텍스트로 출력
ish -c                       # 설정 창
ish --config --home ~/my-ish
```

도움말은 시작하기, 키, 설정 파일, 플러그인·보완 모듈, 호스트 기능, 입력·화면, 진단·로그, 지원 범위, 실제 CLI 옵션으로 나뉜다. 본문 제목 오른쪽의 찾기 버튼 또는 Ctrl+F로 카테고리 이름을 검색한다. Enter로 검색한 페이지를 열고, Esc로 검색 전 페이지로 돌아간다.

화살표로 카테고리를 고르고 Enter 또는 →로 본문을 연다. 긴 문서는 마우스 휠이나 Alt+PgUp / Alt+PgDn으로 스크롤한다. Esc는 본문에서 좌측 패널로 돌아가고, 좌측 패널에서 한 번 더 누르면 창이 닫힌다. 상단 바의 × 또는 Ctrl+D로도 도움말을 닫을 수 있다. **자세히**를 누르면 기본 브라우저에서 ish GitHub 저장소가 열린다.

설정 창은 다음을 제공한다.

| 카테고리 | 설정 |
|---|---|
| 언어·시작 설정 | 언어, 셸, 시작 디렉터리, ESC/Alt 대기, 로그 파일·수준 |
| UI 팔레트 | 도움말·설정 창의 색상 역할과 명도 |
| 플러그인 | 플러그인 선택, 두 페이지가 공유하는 코드·의존성 경로 설정 |
| 모듈 | 프로토콜 등 터미널 기능을 보완하는 모듈 선택 |
| 호스트 기능 | 기능별 on/off, 실제 지원 질의가 있는 항목에만 auto |
| 입력·화면 | 마우스, 프로그램 클립보드 권한, 색 깊이, 스크롤백 한도 |

좌측 상단에서 ish 설정을 고르고, **설치된 확장**에서 각 패키지가 공개한 설정을 편집한다. 패키지 사용 여부는 상단의 **확장 → 플러그인** 또는 **모듈**에서 고른다. 설정 목록을 여는 것만으로 패키지 코드가 실행되지는 않는다.

왼쪽 패널에서 **설치된 확장**(도움말에서는 **참고 자료**) 제목이나 바로 아래 선을 위아래로 드래그하면 두 목록의 높이를 조절할 수 있다. 창 크기가 바뀌면 조절한 비율을 사용한다.

왼쪽 패널 아래 계정 띠에 현재 운영체제 계정과 ish 버전이 표시된다. 계정명을 누르면 계정 정보를 연다. 아래에는 화면 전환 버튼과 프리셋 선택기가 있다. 프로필 버튼 두 개가 들어가는 폭보다 더 줄이면 왼쪽 패널이 아이콘만 표시한다. 아이콘에 키보드 포커스를 두거나 마우스를 올리면 원래 이름이 뜬다. 페이지를 열려면 항목 이름이나 아이콘을 클릭한다. 왼쪽 패널의 여백에서 마우스 왼쪽 버튼을 누르는 즉시 현재 페이지의 카테고리 탐색으로 키보드 포커스가 이동한다. 본문의 여백을 클릭하면 같은 페이지의 본문으로 키보드 포커스가 돌아간다. 여백 클릭만으로는 페이지가 바뀌거나 입력 편집이 시작되지 않는다. 구분선을 오른쪽으로 끌거나 카테고리에서 Ctrl+→를 누르면 다시 펼친다. **도움말**과 **설정**(영문 전환 버튼은 **Config**)을 오가도 설정 초안은 유지된다. 프리셋 목록 맨 아래의 **+**를 선택하고 이름을 입력하면 현재 초안을 새 프리셋으로 담는다. 기존 이름을 선택하면 해당 프리셋이 초안에 적용된다. 디스크에 기록하려면 **저장**을 누른다.

긴 입력값은 접혀 있을 때 끝에 `…`가 표시된다. 편집을 시작하면 전체 값이 줄바꿈되어 나타나며, 드롭다운 후보도 펼친 목록에서 전체 이름을 읽을 수 있다.

UI 팔레트에서 **강조색 1**은 포커스된 버튼과 설정 제목, **강조색 2**는 하단 단축키의 키 글자와 프로필 계정명, **강조색 3**은 좌측 패널의 대표 카테고리 제목과 하단의 Alt 표시, **강조색 4**는 하단 단축키 조각 바탕과 Ctrl 표시에 쓰인다. **주석색 1**은 설명·상태 문구와 구분선 호버에, **주석색 2**는 구분선과 스크롤바에 쓰인다. 스크롤바에 마우스를 올리거나 손잡이를 끌면 화살표와 손잡이가 강조색 1로 바뀐다. `<S> 저장`에서 꺾쇠와 ‘저장’의 글자는 하단 바 바탕과 같은 선택 배경색을 쓴다. 포커스가 있는 패널과 상단·하단 바는 역할에 지정한 색을 그대로 표시한다. 글자색과 배경색이 비슷해도 색을 바꾸지 않으며, ‘기본색’은 해당 글자 또는 배경에 터미널 기본색을 사용한다. 색상 견본 위의 숫자(100~900)만 견본을 읽기 쉽도록 흰색 또는 검은색으로 표시한다. 포커스가 없는 패널의 위젯은 흑백으로 표시되며, 마우스를 올린 위젯만 강조된다. 구분선은 양쪽 패널에서 같은 주석색을 사용한다. 영역을 가로질러 마우스를 움직여도 다음 키 입력은 원래 포커스에 전달된다.

도움말과 설정에서 스크롤바의 위·아래 버튼은 유니코드와 Nerd Font 모두 `△`·`▽`로 표시한다. 하단 키 안내는 두 스타일 모두 `←↓↑→`로 표시한다. 창이 너무 좁거나 낮으면 경고색으로 크기 조절 안내를 표시하고, 창을 다시 넓히면 편집하던 값과 커서 위치가 돌아온다.

`ish -h`는 같은 파일에 직접 선언한 팔레트 변수도 읽는다. 예를 들어 `theme = {"accent": "teal-300"}` 다음 줄에 `config.ui_palette = theme`를 둘 수 있다. 함수 호출·다른 이름을 통한 변경 등으로 값을 확정할 수 없으면 독립 실행한 도움말은 기본 팔레트를 사용한다. 설정창에서 도움말로 이동하면 현재 초안의 팔레트와 아이콘을 그대로 사용한다.

본문 하단 왼쪽에는 작업 진행·결과, 미저장 변경, 적용한 필터, 오류가 표시된다. 긴 경고는 왼쪽 영역에서 필요한 만큼 줄을 바꾼다. 오른쪽 버튼은 **취소**, **저장** 순서다. 본문에서 Tab을 누르면 취소가 선택되고, →를 누르면 저장으로 이동한다. Ctrl+S는 저장 버튼과 같은 동작으로 변경 사항을 파일에 기록한다. 취소는 초안을 마지막으로 저장하거나 불러온 값으로 되돌린다. 두 동작 모두 창을 열어 둔다.

페이지 제목 오른쪽의 옵션 필터·다시 읽기·파일 편집 도구는 아이콘을 클릭해서 실행한다. 값을 편집하는 동안에도 마우스를 올리면 아이콘이 강조되고 이름이 표시된다. 키 입력은 현재 항목에서 계속 받는다. 상단 도구, Ctrl+F/E/R, 하단 바의 같은 단축키는 이번 입력만 Esc처럼 취소하고 해당 도구를 실행한다. 마우스는 같은 버튼에서 눌렀다 뗄 때 실행한다. 저장과 Ctrl+S는 입력값을 검증하고 오류가 있으면 편집을 계속한다. 키보드로는 본문에서 Shift+Tab으로 도구줄로 이동한 뒤 ← / →로 고르고 Enter나 Space로 실행한다. Ctrl+E는 `.ishrc.py`를 외부 편집기로 열고, Ctrl+R은 초안을 버리고 파일을 다시 읽는다. 언어·시작 설정의 기본 편집기(`config.editor`)와 웹 브라우저(`config.browser`)에는 실행 파일과 고정 인수를 지정한다. 공백이 포함된 경로는 따옴표로 감싼다. 비워 두면 편집기는 VISUAL·EDITOR·vi 순서로 선택하고 도움말은 시스템 기본 브라우저를 사용한다. 이미 창에서 바꾼 값이 있으면 저장이나 취소 후 편집한다.

`--config`에는 `--home`, `--lang`, `--no-rc`만 함께 지정할 수 있다. 그 밖의 CLI 세션 옵션은 실제 세션을 시작할 때 사용한다.

## 설정 파일과 저장

설정 파일은 `~/ish/.ishrc.py`다. `--home DIR`이면 `DIR/.ishrc.py`다. 상대 경로는 파일의 디렉터리가 기준이며 CLI 상대 경로는 실행한 디렉터리가 기준이다. 셸의 HOME과 rc 파일은 바꾸지 않는다.

```python
config.lang = "ko"
config.shell = "bash"
config.shell_args = ["-i"]
config.plugins = []
config.mouse = "auto"
config.clipboard = "write"
config.color_depth = "inherit"
config.escape_delay = 0.02
config.scrollback_lines = 10000
config.scrollback_bytes = 32 * 1024 * 1024
config.features = {
    "hyperlinks": "on",
    "enhanced_keyboard": "auto",
}
```

`config` 객체 자체를 재할당하지 않는다. 이전 `config.vt` 구조를 변환하거나 대신 읽지 않는다. `config` 필드는 Python 속성으로 선언하며, 알 수 없는 필드·잘못된 값은 셸 실행 전에 오류로 보고한다.

설정 TUI는 기존 코드와 주석을 유지하고 아래 형식의 관리 블록을 파일 끝에 둔다. 수동 코드 뒤에서 이 값이 최종 적용된다.

```python
# >>> ish settings
config.lang = 'ko'
config.mouse = 'off'
# <<< ish settings
```

기존 파일은 같은 디렉터리에 `.ishrc-backup-...` 파일로 백업한다. 새 파일을 완성하고 검증한 뒤 원자적으로 교체하며, 외부 변경이나 심볼릭 링크 대상 변경을 발견하면 저장을 거부한다. 다른 편집기와의 완전한 파일시스템 트랜잭션을 보장하는 것은 아니다. 손상된 관리 블록은 임의로 덮어쓰지 않는다. 파일을 직접 정리해 다시 읽거나 관리 블록을 통째로 제거할 수 있다.

저장할 때 rc를 다시 실행하거나 플러그인을 로드하지 않는다. 명시적으로 저장한 변경은 다음 세션에 적용한다. 취소는 설정 파일을 쓰지 않는다.

## 값과 우선순위

CLI가 저장 설정보다 우선한다. `--no-rc`는 이번 실행에서 ish 설정 파일을 건너뛴다. 셸의 rc는 원래대로 읽는다. `--login`은 셸에 `-l`만 전달하며, 반복한 `--shell-arg=ARG`는 기본 `-i`를 대체하고 `--login`과 함께 쓸 수 없다.

| 필드 | 기본값 / 허용값 |
|---|---|
| `lang` | None: LANG 자동 감지 후 영어. 명시적 언어가 최우선 |
| `shell` | 계정 로그인 셸, 없으면 SHELL 또는 sh |
| `shell_args` | `["-i"]` |
| `cwd` | 시작한 디렉터리 |
| `plugins` | `[]` |
| `plugin_dir` | `~/ish/plugin/script` |
| `plugin_lib_dir` | `~/ish/plugin/lib` |
| `mouse` | `auto`; `off`, `auto`, `on` |
| `clipboard` | `write`; `off`, `write`, `read-write` |
| `color_depth` | 기본 `inherit`는 본체 터미널의 색 깊이를 따르며 알 수 없으면 PTK 기본값을 사용. 직접 지정하려면 `1`, `4`, `8`, `24` 문자열 |
| `escape_delay` | 0.02초, 0.005~2.0. 느린 연결에서 Alt·방향키가 갈라지면 늘리세요. |
| `scrollback_lines` | 10000, 0 이상 정수 |
| `scrollback_bytes` | 33554432, 0이면 기록 비활성화 |
| `log_file` | None: 파일 로그 사용 안 함 |
| `log_level` | `WARNING`; DEBUG/INFO/WARNING/ERROR/CRITICAL |
| `features` | 기능별 기본 정책, 아래 설명 |

한도는 native 페이지 단위의 대략적인 값이며 프로세스 전체 메모리 상한이 아니다. 스크롤백 CLI 정수 범위는 0~9223372036854775807이다.

## 언어

언어 우선순위는 명시한 설정(CLI 우선), LANG, 영어다. LC_ALL·LC_MESSAGES·LANGUAGE는 ish 언어를 덮어쓰지 않는다. 영어 기본 문구는 코드에 있고 영어 파일 없이 동작한다. 한국어는 제공 언어팩을 사용한다. 사용자 언어팩은 설정 디렉터리의 `lang/LANG.json`에 둔다.

도움말·버전·진단은 rc 코드를 실행하지 않아 --lang·LANG·영어 순서를 사용한다. 설정 창은 rc를 읽으므로 저장 언어를 표시한다. 셸 출력·외부 예외 세부 정보·wire 값·프로그램 식별자는 번역하지 않는다.

## 플러그인·보완 모듈

UI·키·출력·클립보드 보완 모듈은 같은 `config.plugins`와 `plugin_dir`를 사용한다. 별도 보완 모듈 경로나 로더는 없다. 메타데이터 조회는 코드 실행·의존성 설치 없이 수행하며, 발견된 메타데이터가 실행 가능성을 보증하는 것은 아니다.

설정 창에서 플러그인 경로 편집을 마치면 해당 폴더의 플러그인·모듈 목록이 갱신된다. 원래 폴더에 패키지를 추가한 경우 변경분을 저장한 뒤 ↻ 또는 Ctrl+R로 설정 파일과 목록을 함께 다시 읽는다. 선택 해제는 파일 삭제가 아니다. `.py` 수정과 선택 변경은 다음 세션에 적용하고 실행 중 교체하지 않는다.

```python
config.plugin_dir = "/absolute/path/to/ish/bundles/plugins"
config.plugins = ["terminal_history", "terminal_search"]
```

저장소의 [플러그인](../bundles/plugins)과 [모듈](../bundles/modules)은 각각의 폴더에서 직접 선택할 수 있다. 두 종류를 함께 사용하려면 원하는 패키지 폴더를 같은 `plugin_dir` 아래에 복사하고 `config.plugins`에 이름을 나열한다. 기본 경로는 `~/ish/plugin/script/`다.

`--plugin NAME`은 이번 세션의 선택 목록을 대체한다. `--no-plugins`는 저장된 선택을 이번 세션에서 끈다. 설정창의 **확장 → 플러그인**에서 하단 바·팝업 같은 일반 플러그인을, **확장 → 모듈**에서 키·클립보드 같은 보완 모듈을 선택한다. 실제 로딩과 의존성 검사는 같은 PluginManager가 담당한다. [플러그인 개발](PLUGINS.md) · [보완 모듈 API](VT_PROTOCOL_PLUGINS.md)

## 기능별 정책

모든 기능에 켜짐·꺼짐이 있으며, 지원 질의를 구현한 기능만 자동을 제공한다. 설정 화면에 나오는 정책과 실제 지원 조회 결과는 구별된다. 설정 화면은 호스트 질의를 보내지 않는다.

| 기능 | 기본 정책 | 자동을 위한 질의 |
|---|---|---|
| hyperlinks, extended_styles, overline, cursor_color | on | 없음 |
| iterm_graphics | off | 없음 |
| kitty_graphics | auto | Kitty graphics query |
| synchronized_output | auto | DECRQM 2026 |
| enhanced_keyboard | auto | CSI ? u |
| pixel_mouse | auto | DECRQM 1016 |
| clipboard_protocol | auto | DECRQM 5522 |
| scheme_notifications | auto | DECRQM 2031 |

on은 실제 지원 확인과 다르며 이미지 크기·커서 색 복원 등 필수 조건을 생략하지 않는다. 자동은 긍정 응답이 있어야 켠다. `clipboard_protocol`은 전송 프로토콜을 고르며 클립보드 읽기 권한을 부여하지 않는다.

## 입력·클립보드·복원

마우스 off는 호스트 드래그를 유지한다. auto는 프로그램이나 명시적인 클릭 UI 요청에 따라 입력을 받고, on은 내부 선택도 켠다. 호스트는 현재 표시한 내용만 알며 숨겨진 native history·팝업 뒤의 내용을 선택하지 못한다.

셸 프롬프트에서 휠로 이전 출력을 보려면 `ish --mouse on`으로 실행한다. 이때 키보드 ↑·↓는 셸의 명령 기록을 탐색하고, Vim이 마우스를 요청하면 휠은 Vim으로 전달된다. 일반 드래그는 ish가 선택하며, Windows Terminal의 선택은 Shift를 누른 채 드래그한다. 이 동작을 다음 세션에도 쓰려면 설정 창의 **입력·화면 → 마우스 정책**에서 `on`을 저장한다.

Windows Terminal은 전체 화면 프로그램이 마우스 입력을 요청하지 않으면 휠을 방향키로 보낼 수 있다. 이 경우 기본 `auto`의 일반 프롬프트에서는 휠이 이전 명령을 불러온다. 기본형은 Shift+PgUp·Shift+PgDn도 안쪽 프로그램에 전달한다. 본체의 일반 드래그 선택을 유지하면서 이 두 키로 이전 출력을 보려면 `terminal_history` 플러그인을 선택한다. 이 플러그인은 기본 화면에서만 페이지를 이동하며 Vim의 대체 화면과 팝업에서는 키를 예약하지 않는다.

키의 동작은 안쪽 프로그램이 결정한다. 일반 셸에서 Shift+Enter는 Enter와 같은 바이트(CR)로 전달된다. 프로그램이 Kitty 키보드 프로토콜 또는 xterm modifyOtherKeys를 요청하면 해당 형식으로 전달하므로 수정 키를 구별할 수 있다.

도움말·설정 창이나 팝업을 닫을 때 ish는 닫힌 화면이 받은 마우스 보고를 걸러낸다. 같은 입력을 계속 관리하는 동안 일반 키와 붙여넣기의 순서를 보존하며, 마우스가 필요한 화면으로 복귀하면 그 화면의 새 보고를 처리한다.

설정창이나 도움말을 단독으로 실행해도, 시작 시 마우스 추적 상태 질의에 응답한 호스트에서는 종료할 때 추적 해제 응답까지 읽고 호출한 셸로 돌아간다. 응답 뒤의 바이트는 셸이 읽는다. 질의를 지원하지 않거나 종료 응답이 제한 시간 안에 도착하지 않는 호스트에서는 이미 전송 중인 보고가 다음 프롬프트에 남을 수 있다.

프로그램의 직접 클립보드 권한은 기본 write다. 읽기를 원할 때만 read-write를 선택한다. 이것은 평소 본체 터미널의 복사·붙여넣기와 별개다. `clipboard_system` 보완 모듈은 Windows/WSL이나 X11에 연결하며, 원격에서는 실제 전송 경로가 있어야 한다.

정상 종료·중지 시 관찰하고 변경한 터미널 상태를 복원한다. 프로그램이 바꾼 제목은 마지막 값을 유지한다. SIGKILL·호스트 소멸 같은 예외 종료의 완전 복원은 목표가 아니다. 자세한 범위는 [복원 계약](VT_RESTORATION.md)을 참고한다.

## 진단·로그

```sh
ish --version
ish --diagnose
ish --log-file ./ish.log --log-level INFO
```

조회 명령은 rc·플러그인·셸·native 라이브러리를 실행하지 않고 설정·로그 파일을 만들지 않는다. 진단은 기본값과 CLI 선택을 보고하며 실제 세션 지원을 확인했다고 표시하지 않는다.

파일 로그는 진단만 기록하고 native 입출력·클립보드 내용·native 로그 본문을 기록하지 않는다. 콘솔 로그는 활성 터미널 화면 밖에서 출력한다. 테스트 하네스의 숨긴 `--dump-state`는 화면 문자를 포함하는 명시적 진단이며 일반 로그와 다르다.
