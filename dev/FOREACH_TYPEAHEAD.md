**csh/tcsh foreach 선입력 표시 수정 — 2026-09-10**

현재 tcsh의 편집 모드 복원은 `postcmd` 훅에서 수행합니다. 사용자 명령에 `_ish_restore_editor;`를 붙이던 방식은 히스토리를 오염시켜 제거했습니다. 자세한 내용은 아래 히스토리 후속 수정에 기록했습니다.

실행 중 `precmd`·`postcmd`를 교체하는 경우는 [훅 복구 문서](D:/Programs/ish/dev/HOOK_RECOVERY.md)에 기록한 기본 프롬프트 경계의 감시로 처리합니다. `_recover()`에서 프로세스 대기 상태만으로 복구 명령을 넣는 방식은 다시 활성화하지 않았습니다.

`foreach x (\`오래걸리는_명령어\`)`에서 첫 보조 프롬프트가 늦게 나오는 것은 명령 치환의 결과를 기다리기 때문입니다. 일반 셸과 ish에 같은 입력을 보내 비교했습니다. 사용자가 보고한 차이는 실행 결과보다 보조 프롬프트와 선입력 표시였습니다.

기존 ish는 tcsh의 보조 프롬프트를 제거하고 prompt_toolkit 입력창을 열었습니다. 이때 `tcflush(TCIOFLUSH)`를 호출하고, 이미 셸에 전달한 입력의 복사본으로 ish 입력을 복원했습니다. 셸 내부에 이미 읽힌 입력까지 되돌릴 수 없으므로 프롬프트 수신 시점을 새로운 입력 요청으로 취급하는 것은 적절하지 않습니다. 또한 tcsh의 `edit`를 계속 해제해 일반 tcsh가 보조 프롬프트에서 다시 표시하는 입력도 달랐습니다.

변경 후 기본 프롬프트는 ish가 편집하고, 명령 실행부터 보조 입력 완료까지는 csh/tcsh가 입력을 처리합니다. 입력을 PTY로 계속 전달하며, 보조 프롬프트를 이유로 flush하거나 UI에 재주입하지 않습니다. 새로운 tcsh 통합 스크립트는 `prompt2`를 감싸지 않습니다. 사용자의 `edit` 설정을 저장하고 명령 평가 전에 복원합니다. 기존 형식의 보조 프롬프트를 받더라도 그 내용은 원래 출력 순서대로 전달합니다.

관련 변경:

- [base.py](D:/Programs/ish/src/ish/shell/base.py): C shell의 보조 입력 동안 기본 프롬프트까지 기다립니다. 대기 중인 프로세스라는 이유만으로 복구 명령을 주입하지 않습니다. 여러 줄로 붙여넣은 C shell 블록은 함께 전송합니다.
- [scripts.py](D:/Programs/ish/src/ish/shell/scripts.py): tcsh에서 `precmd`는 기본 프롬프트의 편집 모드를 잠시 해제하고, `postcmd`는 명령 실행 전에 사용자의 편집 모드를 복원합니다. 기존 사용자 훅과 종료 상태를 보존합니다.
- [sequencer.py](D:/Programs/ish/src/ish/shell/sequencer.py): callback이 반환한 보조 프롬프트를 해당 스트림 위치에 출력합니다. tcsh가 인터럽트 후 훅을 건너뛰며 표시하는 caret 형식의 기본 프롬프트도 인식합니다. 실제 기본 프롬프트를 확인한 뒤 상태를 다시 동기화합니다.
- BSD csh가 `? ? READY>`처럼 같은 줄에 프롬프트를 이어 쓰는 경우, ish의 기본 입력창이 다시 그려져도 앞부분을 보존합니다. 상태 갱신용 내부 명령 때문에 불필요한 줄바꿈을 추가하지 않습니다.

보조 입력 구간에서는 ish의 자동완성·키 바인딩을 사용하지 않고 셸의 입력 처리를 사용합니다. tcsh에서 사용자가 `unset edit`를 설정했다면 그 설정도 유지합니다.

**재현 예제**

```csh
foreach x (`sleep 3; echo one two`)
echo $x
end
```

첫 줄을 실행한 후 3초 안에 나머지 두 줄을 입력합니다. 일반 tcsh는 보조 프롬프트와 함께 선입력 내용을 다시 표시할 수 있습니다. ish에서도 해당 동작을 유지합니다. `end`까지 모두 입력한 상태에서 별도의 ish 보조 입력창을 다시 열지 않습니다.

**후속 수정: tcsh 히스토리 오염 제거 — 2026-09-10**

명령 앞에 붙인 `_ish_restore_editor;`는 echo를 숨기더라도 tcsh 히스토리에 남았습니다. `!!`를 반복하면 접두부가 누적되고, `!!:1` 같은 인수 선택도 내부 명령을 기준으로 해석됐습니다.

이제 `_exec()`는 사용자 명령을 그대로 보냅니다. tcsh의 `postcmd`는 기본 프롬프트에서 `edit`를 해제한 상태에서도 실행되므로, 이 훅에서 저장한 편집 모드를 복원합니다. 이전에 `postcmd`를 사용할 수 없다고 판단했던 내용을 바로잡았습니다. [tcsh 실행 루프](https://github.com/tcsh-org/tcsh/blob/master/sh.c)와 [특수 alias 구현](https://github.com/tcsh-org/tcsh/blob/master/tc.func.c)을 확인하고 실제 tcsh에서도 검증했습니다.

- 기존 `precmd`·`postcmd`와 명령 종료 코드를 보존합니다. 사용자 `postcmd`가 `\!#:q`로 참조하는 명령 내용도 일반 tcsh와 일치합니다.
- 내부 상태 갱신용 파일을 `source`하는 동안에는 `postcmd`를 잠시 해제합니다. 이 파일의 각 줄에서 편집기를 조기에 복원하거나 사용자 훅을 추가 호출하지 않습니다.
- 문법·히스토리 오류나 `!!:p`는 `postcmd`를 건너뛸 수 있습니다. 다음 프롬프트에서 임시 `unset edit` 상태를 사용자의 원래 설정으로 덮어쓰지 않도록, 해제 여부를 따로 기록합니다.
- Ctrl+C 후 훅을 건너뛴 프롬프트를 복구할 때는 빈 줄로 동기화합니다. 복원 명령을 히스토리에 추가하지 않습니다.
- 이전 버전이 이미 저장한 사용자 히스토리 파일은 수정하거나 삭제하지 않습니다. ish를 재시작하면 새 명령부터 적용됩니다.

[test_tcsh_history.py](D:/Programs/ish/tests/test_tcsh_history.py)는 테스트용 세션의 히스토리를 초기화한 뒤, `!!` 반복 실행, 인수 선택, 기존 훅의 호출·상태·명령 내용, 오류 후 편집 모드, 사용자 `set/unset edit`를 일반 tcsh와 비교합니다. foreach 테스트에도 Ctrl+C 복귀 후 히스토리 검사를 추가했습니다.
